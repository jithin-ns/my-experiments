Hi Team,

I would like to share a few recommendations that I believe would help improve delivery efficiency and project execution for the remainder of the project as well as future engagements.

1. Scope Management for Design and Standardization Changes

UI changes identified during Bagel reviews that arise due to differences between the approved UX designs and Bagel design standards should be treated as Change Requests (CRs) rather than development defects.

Similarly, we have received requests from the Business Analyst team to standardize screens across the application, even though the implemented screens were developed exactly as per the approved UX designs. This has required rework across multiple screens (at least six screens), introducing additional effort that was not part of the original implementation scope.

Although tools such as Amazon Q have helped accelerate some of this work, the effort is still significant considering the current project timeline.

For a fixed-price, fixed-scope project, such changes should ideally:

- be accompanied by an appropriate timeline adjustment, or
- be treated as formal Change Requests (CRs) and scheduled separately from the committed scope.

2. Timeboxing Development Activities

A structured timeboxing approach could help improve productivity while ensuring critical issues continue to receive attention.

- Reserve the first half of the day exclusively for planned development work.
- During this period, developers should only be interrupted for genuine showstopper issues impacting SIT or UAT execution.
- Avoid posting non-critical requests in group chats during the focused development window.
- Use the afternoon (after the prioritization call) to address UAT defects, SIT issues, and other agreed priorities.

3. Reduce Context Switching

Developers are currently expected to switch frequently between development work, SIT defects, UAT defects, and BA-driven rework. This constant context switching impacts productivity and increases the likelihood of defects.

Wherever possible:

- Batch similar work items together.
- Avoid assigning new tasks immediately unless they are genuinely critical.
- Reserve "ASAP" or urgent communications for actual business or testing blockers.

4. Improve Communication for Shared Components

Changes to reusable components should be communicated proactively to all dependent developers. A clear communication mechanism for interface or behavior changes would reduce integration issues and unnecessary rework.

5. Improve Reusable Component Design

Where practical, reusable components should be designed to accept raw data while encapsulating formatting and presentation logic internally.

This would improve consistency, reduce duplicated formatting logic, simplify component consumption, and minimize integration defects.

6. Strengthen the Development Process

Introducing mandatory Git Pull Request reviews and consistent peer code reviews before merging would help identify design and implementation issues earlier, improve knowledge sharing, and reduce rework during SIT and UAT.

These recommendations are intended to improve delivery efficiency, reduce avoidable rework, and help the team focus on delivering committed scope with better predictability.

Thank you for your time and consideration.
